**Статус:** ⏸️ отложена (за рамками первого релиза). Активируется по запросу, когда
появится конкретная модель CMF by Nothing и необходимость в её данных.

---

## 1. Цели и границы

### Что входит в фазу
- **Нативный forwarder под CMF by Nothing** — устройство/платформа, для которой на старте
  нет ни агрегатора, ни API (см. §1 «Что НЕ входит в первый релиз»).
- Переиспользование **phone-hub пути** (custom channel `POST /eve/v1/phone-hub`,
  Bearer-токен, нормализация, `raw_samples`, дедупликация) — архитектурно фаза 7 ничего
  не меняет, добавляется только новый forwarder-источник.
- Маппинг полей CMF → нормализованный `payload` (по аналогии с §20.1 для Android/iOS).

### Что НЕ входит
- Любые изменения основной архитектуры ingestion — phone-hub уже унифицирован (§2, §6.1).
- Платные агрегаторы (Terra/Spike) — отменены окончательно (§1).
- Прямой вендор-API — отложен; phone-hub покрывает потребность единообразно.

### Ключевое архитектурное решение фазы
CMF подключается **тем же phone-hub путём**, что и Amazfit/Huawei: данные попадают в
Apple Health / Health Connect (если устройство пишет в системное хранилище) либо через
свой forwarder, и шлются на наш webhook. Нового канала/пути ingestion не появляется.

## 5. Детали реализации (TBD — наполняется при активации фазы)

### 5.1 Выбор forwarder'а
На момент написания спецификации (2026-08-11) для CMF by Nothing нет ни готового
forwarder'а, ни подтверждённого API. При активации фазы:
1. Проверить, пишет ли CMF в Apple Health / Health Connect (как Amazfit/Huawei).
2. Если пишет — переиспользовать существующий forwarder (mcnaveen/health-connect-webhook
   для Android, «Health Webhook» для iOS); нужен только маппинг полей.
3. Если не пишет — исследовать наличие официального API / SDK; при отсутствии —
   рассматривать self-build нативного forwarder'а (Android-приложение под Health Connect,
   либо iOS-SwiftUI). Зафиксировать решение в STATUS.md.

### 5.2 Маппинг полей (по аналогии с §20.1)
- Зафиксировать нормализованный формат payload для каждого `metric` (sleep/steps/HR/
  active_calories/workout), исходя из того, что реально отдаёт CMF/его forwarder.
- Нормализующий слой в route-хендлере phone-hub (маппинг полей по `platform` +
  `device_label`).

### 5.3 Онбординг устройства
- На шаге 7 онбординга (§10) добавить выбор «CMF by Nothing» с инструкцией под выбранный
  forwarder (по аналогии с Android/iOS-инструкциями).
